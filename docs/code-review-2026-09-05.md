## A. Crashes, memory safety, ABI (Rust crate, JNI, shim)

**A-1 · medium · `events.rs:335,350` ← `wasm.rs:507-527` — Feed/Kill index the world with
an unchecked caller integer.** `mc_event_feed(i, …)` builds `Event::Feed { i: i as usize }`
and `apply_event` reads `sim.w.alive[i]` directly. Any `i >= MAXN` or a negative `i` (a
huge `usize` after the cast) is an out-of-bounds panic: a WASM trap, or on Android
(`panic = "abort"`) a process abort. The oracle (`events.js` feed/kill) reads `undefined`
and treats it as a logged no-op. Today only indices from `pickAt`/`mc_org` reach it, so
this is latent; it is the one place the ABI trusts an index it did not hand out. Fix: guard
`i < MAXN` in `apply_event` (the event is logged before the match in both implementations,
so the log stays identical; no draw, no fingerprint change).

**A-2 · medium · `levels.rs:392,420` — the level census loops iterate `0..self.w.n`, not
`n_slots()`.** `World::n` legitimately exceeds `MAXN` once the pool is full
(`world.rs:308-319` documents it and provides `n_slots()` for this reason; every other
observer uses it). `lvl_share` and `lvl_near_pt` run every 20 ticks in L7/L9/L11; a bloom
that fills 6,000 slots panics there. Fix: `0..self.w.n_slots()`. Observer-only, draw-free.

**A-3 · medium · `snapshot.rs:642-643,703,720,737,739` — a well-formed but corrupt
snapshot is accepted, then aborts the process on the next tick.** `parse` checks header
shape and column lengths, not the values other code indexes with: `c_n` is not bounded by
`MAXCORPSE` (`observatory.rs:475`, `frame.rs:608`, `step.rs:851` then index past
`c_alive`); `c_free`/`free_list` entries are unchecked (`spawn_corpse` writes
`c_alive[k]` unguarded); a live slot may carry `sp >= 7` (`tr[sp]` panics in the tick);
`sources` may be empty (`observatory.rs:501` reads `sources[0]`). `load` returns `Ok`, the
shell restores it, and the abort lands before any autosave can replace the file — a
corrupted autosave becomes a crash-at-boot loop, which is exactly what the "a refused load
never destroys the world" invariant (status log 2026-09-04) was meant to prevent.
`bin/snapshot.rs` §4 tests only bad magic and truncation. Fix: value checks in `parse`
before `Ok(())`, and the cases added to `bin/snapshot.rs`.

**A-4 · medium · `snapshot.rs:216-223,228-235` — length-prefixed vectors reserve before
checking availability.** `usizes()` and `f64s_vec()` do `Vec::with_capacity(n)` from a
four-byte field: a flipped length at the free list or census ring reserves up to 32 GB on
64-bit (alloc failure → abort) or hits "capacity overflow" on wasm32, instead of the
`Err(truncated)` the refusal contract promises. `bytes_vec` next to them does it right by
`take()`-ing first. Fix: `if n > remaining { return Err }` or a hard cap
(`MAXN`, `MAXCORPSE`, `REC_N * regions`).

**A-5 · medium · `wasm.rs:15-25` + `MainActivity.kt:161,178,276,1150,1903`,
`Help.kt:197` — the UI thread reads core `Vec`s the render thread reallocates.** `s()`
hands out `&'static mut Sim` with no synchronisation; `app.rs:480-481` says "the shell must
call them from the render thread". `tickHud` (every 250 ms) and `refreshData` (4 Hz) call
`Native.traitText`/`specNum` on the UI thread; those read `sim.tr[sp].loci` and
`sim.grammar`, which the render thread replaces wholesale in `Sim::load`
(`snapshot.rs:586`) and in `mc_frame_grammar_build` (`wasm.rs:951`, called from
`Renderer.init` on every `surfaceCreated`, i.e. every unlock). The window is nanoseconds
and the strings themselves are `&'static str`, so what races is a `Vec` header — small,
rare, but real undefined behaviour on `&mut` state. Fix: names, flags and identity colours
are static per build; fetch them once before the surface exists (as `live` already does
for flags) and never call `Native.*` from `tickHud`/`refreshData`/`Help`.

**A-6 · medium · `wasm.rs:1429-1434` — `imp()` unwraps a static only `mc_impact`
fills.** `mc_impact_num/mover/mover_ptr/len` all abort if called before the first
`mc_impact`. Both current callers happen to order the calls correctly; nothing enforces it.
Fix: `get_or_insert_with(Default::default)`.

**A-7 · low · `events.rs:182,312`, `fields.rs:88` — the oracle's `+v || 0` NaN guard is
not carried across.** The JS `locus`/`wallSet`/`make_wall` paths coerce NaN to 0; Rust's
`jmax/jmin` (correctly) propagate it, so a NaN slider value is stored into the locus and
every member of that species stops dying and dividing (`en <= 0` and `en > frac*cap` are
both false on NaN) while the fingerprint sums NaN. Reachable only through a shell bug.
Fix: `if v.is_nan() { 0.0 }` at the three sites; identical for every finite input.

**A-8 · low · `math/rem_pio2_large.rs:29,41` — one `cfg(target_pointer_width)` remains
in `math/`.** wasm32 and aarch64 get different `IPIO2` tables; they agree wherever the
index stays below 66 and the huge-argument path needs |x| ≳ 2^1560, so the tick cannot
reach it. It still contradicts `MATH-PROVENANCE.md`'s premise. Fix: one table.

**A-9 · low · `observatory.rs:454,458,976` — `f64::ln` is platform libm.** `math/mod.rs`
says never to call `f64::sin` "and friends"; `ln` is a friend with no vendored
counterpart. The results land in rec channels 129-132 (occupancy entropy) and
`Indicators.variety`, which no port gate compares — so cross-platform identity of those
channels is unmeasured, not proven. Fix: vendor `log` with the same discipline.

**A-10 · low · `rust/wasm/core.js:450` — the shim's corpse display-list view is
under-sized.** `1500 * 4` where `CORPSE_STRIDE` is 6 (`frame.rs:464`; the oracle allocates
`1500 * 6`). `fingerprint-frame.js` compares `undefined` past corpse 1,000.
`mc_frame_const(3)` exists so this would not be hard-coded. Fix: use it.

## B. Product-visible bugs (Android app)

**B-1 · medium · `MainActivity.kt:1150-1152,1387`, `WorldView.kt:852`,
`Evolution.kt:101` — "species colour" reads the tint dial's far rail, not the species.**
All four call `Native.specNum(sp, 0, 0, c)`. For a species with a tint plane,
`frame.rs:209` returns `tint_rgb(base, 1.0)` at bucket (0,0): hue −52°, lightness −0.14.
Drifta and Bacillus carry a Thermal locus, so census chips, drawer pills, the specimen dot,
seed-picker rows, Vitals rows, population lines and legends, Traits bands and Evolution
headers show them in a hue that is neither their body on the water nor their Help-page dot.
`Help.kt:197-205` (`identity()`) documents exactly this trap and reads the middle bucket.
Rule 7 says species colours belong to the world; the chrome shows a genotype extreme as
identity. Fix: one shared `identity(sp)` and every `speciesColor` calls it.

**B-2 · medium · `WorldView.kt:260-268,631-635` + `snapshot.rs:576-601`,
`levels.rs:486-511` — the undo slot and the intervention log survive world replacement.**
Only `resetWorld` calls `undoClear`; `startLevel`, `restartLevel` and `load` do not, and
the crate's `Sim::load` and `level_start` clear neither `sim.undo` nor `sim.iv_log`
(`start_apply`, `starts.rs:174-176`, does both, with the right reasoning). Two
consequences. (a) Pour in the sandbox, open a level within the 10 s chip window: the chip
still offers "undo · poured mineral", and tapping applies the sandbox's undo to the level
world (`Fertilize` on its cells, or `SourceRemove`/re-insert into a sky the level locks).
`Undo::Kill` after a load calls `spawn` — a heading draw — so the loaded world's stream
diverges from an uninterrupted run. (b) Deterministic, no timing: after `begin()` the
Events page lists the sandbox's interventions, and `impact()` (`impact.rs:142-151`) with
`entry.tick > w.tick` computes `avail < 0`, so the card prints "watching impact… −3311%".
Same after a manual load of an older save. `level_start` also leaves its own founding
`LightMul` in the slot (`levels.rs:502-504`), so undo after starting L1 restores full sun.
Fix: clear `undo`, `iv_log` and `frame.cand` in `Sim::load` and `level_start`; the ABI has
no `mc_iv_clear`, so the crate has to do it.

**B-3 · low · `MainActivity.kt:1505` — returning from an experiment to a kept pond
ignores a refused load.** `world.load(pond) {}` discards `ok`; on refusal the player is
"in the sandbox" on the stopped experiment's world and the next pause autosaves it over
the kept pond. Fix: on `!ok`, `resetWorld`.

**B-4 · low** · `MainActivity.kt:1886` sets `sunSel`/`sunGripShown` on the UI thread
before the posted layout lands (stale slider values for `hot`, ≤ 1 frame window);
`MainActivity.kt:365,373,961,973,1121` raw pixel paddings where everything else uses

**B-5 · nit** · `Evolution.kt:206` colours prose amber, and `styles.xml` `colorAccent`

## What was checked and found sound

- RNG: `mulberry32` term for term; every draw in the tick at the same branch depth as the
  oracle; founding and `SpawnPack` argument order; `n_slots()` equivalence to JS reading
  `undefined`; no draw in any observer, level, frame or impact path.
- Float semantics: every f32 read widened and store narrowed with V8's rounding; `jmin/
  jmax` NaN and ±0 semantics; `to_int32`/`to_i16`/`js_round`/`wrap` checked against Node
  22; operator association preserved at every compared site; no `mul_add`, `powi`, or std
  transcendental in the tick. Math module matches fdlibm 5.3 as V8 carries it; `pow`
  carries V8's whole-denominator path; `hypot` is V8's Torque builtin.
- Spatial hash, wall faces, diffusion bodies, `x_pass_blocked`/`march_mul` termination.
- Snapshot: malformed input (bad magic, truncation, shape mismatch, unknown key/state) is
  refused without touching the live world, observer memory included — the bin proves it.
- JNI: all 86 `external fun`s match the exports 1:1 in name and signature; ByteBuffers
  wrap a leaked, never-resized `Sim`; results return null with the exception pending;
  negative indices clamped.
- App: every mutation crosses the command queue to the render thread; `AtomicFile`
  save paths; boot/unlock/recreation never re-found or reload over a live world; resource
  arrays match every index in both locales; signing config only on `release`; no
  minification, so JNI methods survive.
- Build: `dist/` and `species_gen.rs`/`species-normalized.json` regenerate byte-identical;
  generators are platform-independent (shortest round-trip numbers, sorted keys, no locale
  or time); both baselines match the sources they certify.
- CI ↔ `npm test`: every `npm test` step runs in CI; the port job runs every claim in
  CLAUDE.md (generated-table diffs, `port:math`, `selfcheck`, `conform:core`,
  `port:check`, `port:snapshot`, K6 + levels + `starts:check` on WASM). Exit codes of
  every other harness are real. No `Math.random`/`Date.now` feeds any baseline.
- Hygiene: largest tracked file 400 KB; no secret beyond the documented keystore; no
  per-file GPL header in the sim sources.

## Three questions the review cannot settle

1. **Which core is the acceptance authority?** Rule 11 says the crate; `test:full` and
   the acceptance job say `dist/core.js`. If the answer is "both, until port:check
   retires", write that down and add the `MC_CORE` variant now, before the first Rust
   ecology change makes the two disagree.
2. **Is the snapshot format hostile input or trusted?** The refusal contract treats it as
   hostile (magic, truncation), the value checks treat it as trusted. A phone's own
   autosave is the only writer today; the crash-at-boot loop in A-3 is the cost of the
   inconsistency either way.
3. **Do Mycora and Necro stay deferred with D-1 in the record?** Their re-entry
   conditions were written against measurements the cooldown rule invalidates.
